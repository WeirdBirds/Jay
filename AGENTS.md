- Do not claim repository files were read, named files or scene states were inspected, or runtime behavior was verified unless the exact files, state, reproduction, and every requested scene or interaction case were checked and concrete evidence is cited; state evidence-backed findings, inspect the current diff, and cite the relevant error trace, runtime data, compiler/reflection output, API metadata, actual generated source, and minimal reproduction; make only the smallest evidence-backed change and avoid unrelated refactors; make changes only from verified evidence; verify assumptions with the smallest targeted probe; base the fix only on verified evidence; trace the reported failure to this concrete evidence before editing; isolate the failure from that evidence; read the failing stacktrace and inspect the exact affected data first; diagnose only from that evidence and make the smallest patch directly required by the verified cause; inspect and report the actual stack trace, reflection evidence, and generated artifact before changing code; reproduce the issue minimally from that evidence; then reproduce the issue with a minimal reproduction, trace the failing data path and ownership contracts, and validate the root cause with targeted tests or probes; isolate one hypothesis at a time with one minimal, reversible, measurable change, preserving known-good behavior until validated; treat stacktraces, compiler metadata, and reflection output as primary evidence; reproduce failures minimally and change only the smallest set of files implicated by that evidence, making the narrowest proven patch and avoiding speculative or unrelated changes; for visual bugs, first reproduce in a controlled minimal scene and validate positions, coordinate conventions, face orientation, normals, and UV mapping together in that minimal single-model scene with screenshots or instrumentation before changing behavior, for visual bugs, reproduce, run the app, capture and inspect the actual application-window screenshot using the specified screenshot tool, and use evidence-driven instrumentation before diagnosing or changing rendering/importer logic, capture and inspect it again after every rendering or import change, and change behavior only when that evidence identifies the fault, and retain only fixes supported by observed evidence before declaring success; use observed image evidence for the next hypothesis rather than guessing, and do not claim a graphics/import fix complete until reproducing the issue, capturing the requested app-window screenshot, and visually verifying the expected rendered result; when testing importer or asset-format changes, clear relevant generated caches before rebuilding and validating; before changing importer behavior or source assets, instrument and validate each import/render pipeline stage with minimal diagnostics, testing each plausible cause—including scene scale, camera placement, format and coordinate conventions, parsed mesh data, transforms, bounds, handedness, winding, normals, and UVs—independently with a minimal known asset before committing behavioral changes or applying broad corrective flips; do not apply format-conversion workarounds or corrective heuristics before isolating the responsible subsystem with measurements and visual evidence, and revert unproven fixes, and stop and reassess when evidence contradicts the hypothesis.
